# Magpie: five-minute manual check

Load the extension and pin its icon. Keep `Downloads/Taste/` visible. Use a normal site with images, or the included fixture page: run `python -m http.server 8765` in the Magpie folder and open `http://localhost:8765/tests/fixtures.html`.

**Known platform limit:** Chrome for Testing 151 still prompts with “Ask where to save” on despite `saveAs: false`. First try one save with that setting on to check your Chrome version. For the remaining dialog-free tests, switch it off at `chrome://settings/downloads`. The requested guarantee with the setting on is unfulfilled.

- [ ] **Normal image:** on a normal site, right-click an image → **Save to Magpie**. One file and one matching `meta/<base>.json`; green ✓; no file picker with the preference off.
- [ ] **WebP:** save a WebP (the fixture includes one). File ends in `.webp` and opens correctly.
- [ ] **Data URL:** save the fixture's **Data URL PNG**. File opens and its sidecar includes the original `data:` URL.
- [ ] **Hover shortcuts:** refresh the page after updating Magpie. Hover an image and press **Ctrl+Shift+E**: immediate image and JSON, no menu or preview. The JSON describes the hovered image even if another element uses the same URL. Press the shortcut over empty space: red badge, no file. Change a binding at `chrome://extensions/shortcuts` and try it.
- [ ] **Cursor confirmation:** after right-click, hover and confirmed snip saves, a tiny green check appears beside the cursor only when the image and enabled JSON finish. It follows movement for about a second, stays inside the page edges and never blocks clicks or changes focus/layout. Rapid saves show one check. Brief focus changes must not erase it immediately. Discard, failed saves and pending previews show none. Start a snip while a check is visible: the check must not appear in the saved PNG. After updating/reloading Magpie, save on an already-open page without refreshing: the check should recover automatically (it may start in the upper-right corner until the pointer moves).
- [ ] **Quiet downloads:** the bubble must stay closed for right-click, hover and confirmed snip saves, including their JSON files. Check download history still contains them. Turn off **Hide Chrome's download bubble during saves**, save again and check Chrome's usual UI returns. Turn it back on. A later unrelated download should use Chrome's usual UI.
- [ ] **Preview before save:** press **Ctrl+Shift+Y**, drag an area, release. A small preview shows the cropped image and its pixel dimensions. No files or success badge appear yet. The page layout stays still. Press **Enter**: one PNG and its JSON appear. No dark tint, selection border, or preview card is in the PNG. `type` is `snip`, `image_url` is `null`, and `snip_rect` is populated.
- [ ] **Removed feature:** image menus and shortcut settings offer no love action. Preview has only Save and Discard, Save starts focused, Tab / Shift+Tab cycles between them, and L does nothing. New JSON has no `love` key and filenames have no `_love` suffix. Holding Shift during selection still produces an ordinary snip.
- [ ] **Discard:** create previews and try **Discard** and **Esc**. Both close the card without files or success feedback. Click **Save** on a later preview to check mouse confirmation.
- [ ] **Timeout:** leave a preview untouched for 60 seconds. It disappears silently and creates no files.
- [ ] **Leave / replace:** open a preview, switch tabs and return: it is gone. Repeat with a page reload, then with starting a new snip. The old card never saves and the new selection works.
- [ ] **Preview off:** turn off **Preview snips before saving** in Options. Drag a snip: it immediately saves as before. Turn preview back on.
- [ ] **Cancel:** invoke a snip and press Esc; invoke again and click without dragging. Overlay disappears and no files are added.
- [ ] **Restricted page:** open `chrome://extensions` and press the shortcut. Red !, no overlay or file. One descriptive service-worker console error is expected for this intentional failure.
- [ ] **Duplicate:** save the same image rapidly twice in the same second. Both survive, with ` (1)` on one name, and each JSON's `file` matches its image. If necessary, repeat until the timestamp is the same.

If time allows: hover-save the fixture's Blob PNG; try an image beneath a transparent overlay, inside an open shadow root, a cross-origin iframe, and an `about:srcdoc` frame. Move from an image into a frame and back before saving to check stale coordinates cannot save the previous image. Change the options folder and disable metadata, then save again; verify the new folder has only the image. Restore your preferred options. Inspect the service worker: normal successful actions should have no errors.

Developer checks: with a preview open, stop its service worker from Chrome's service-worker inspector and confirm the card still saves once. Replaying an expired or replaced token must write nothing. Large/noisy snips may save directly instead of previewing when they exceed the documented temporary-storage budget. Test a selection near a page edge and at different browser zoom levels; the card should remain within the viewport.
